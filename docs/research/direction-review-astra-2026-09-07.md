# 演进方向评审（Codex gpt-6-astra，2026-09-07）

评审输入：`direction-brief-2026-09-07.md`、三份调研、`docs/protocol.md` Wire Format、`docs/standalone-distribution.md`、`docs/verification.md`、`bin/devicehubctl`、`Sources/action_sender.m` main()。基于提交 `a6ff96a`，只读评估。以下为原文。

---

**推荐 D4：以 D2 做四周受控试用版，保留现有 helper 作协议对照；D1 按需启用，D3 到第四周依据数据决定。** 第一目标是让 agent 稳定完成"看屏幕—操作—确认结果"，而不是补齐所有 adb 动词。

**需拍板**

- **Q1／产品范围与路线** | 来源：用户、文档、自查 | 归属层：业务 | 根因：已明 | 影响：决定四周能否形成可用闭环，避免时间消耗在底层重写。

  建议首批面向拥有已配对 iOS 27 真机的开发者、测试工程师和 agent 框架作者。两周内部 alpha，四周受控试用；暂不定位普通消费者工具或通用 iOS 测试框架替代品。

  MVP 包含设备选择与诊断、截图、tap/swipe/long、Home/Recents、按键、Unicode 输入、启动 App、基础日志，以及共用一套会话逻辑的 CLI/MCP。接受截图坐标作为主要定位方式，UI 树作为增强能力。

  | 路线 | 独立判断 |
  |---|---|
  | D1 原生 raw-XPC | 能减少 Swift ABI 风险，但仍依赖 Apple 主机栈；不作为首月并行主线。 |
  | D2 Python | 已有真实点击证据，复用隧道和设备服务，最适合验证产品价值。 |
  | D3 Go/Rust/C | 当前收益不足以抵消隧道、配对和协议维护成本；若启动，先评估扩展 go-ios。 |
  | D4 分阶段 | 推荐。D3 是可选后续，不是预定终点。 |

- **Q6／许可证与产品化方式** | 来源：文档、自查 | 归属层：业务 | 根因：已明（GPL 基线；具体发行边界另审） | 影响：决定 Python 后端能否直接成为发行产品，以及后续是否需要独立实现。

  建议接受 GPL 兼容的开源设备后端，先做内部试用。上游 LICENSE 是 GPLv3，`ios-peer-tools.md` 中的 MIT 标注不能采用；正式发行仍需核对锁定版本及依赖许可证。GPL 不禁止商业使用；内部使用与向客户分发义务不同。拆成子进程或套 MCP，不自动保证闭源部分免受影响。如果"闭源嵌入式 SDK"是硬要求，应在早期单独拍板，届时提高 D3 优先级。Mac-free 有明显潜在价值，但要用"新主机首次成功操作所需时间"验证。

**可自助修**

- **Q2／会话与延迟架构** | 归属层：会话 | 根因：已明 | 需要长生命周期会话，不必第一天就做独立常驻 daemon。默认 `tap` 先跑 descriptor helper 再跑发送 helper，两次各有 700 ms 尾部等待，约 1.4 秒；一次调用内已能生成完整 swipe，因此需要会话的是跨请求拖拽、实时输入和连接复用。断线后重建并重新发现服务，不得自动重放结果未知的点击或输入。
- **Q2／截图与画面流** | 归属层：服务 | 根因：未明 | DVT 单帧先交付，dtscreencaptured 限时调研，dtremotedisplayd 后置。截图返回帧编号、采集时间、尺寸和方向。barrier 回复不等于 App 已处理事件、更不等于新画面已呈现。
- **Q3／UI 树与视觉定位** | 归属层：服务 | 根因：未明 | 可接受"截图＋归一化坐标"为 MVP 主路径。数日内调查 accessibility 完整响应是否含 frame/hit-test、VoiceOver 相关服务是否暴露几何信息、视觉模型/OCR 作为带置信度的候选定位。动作需绑定观察帧及方向。
- **Q4／文本输入** | 归属层：服务 | 根因：未明 | HID 用于快捷键/方向键/删除/确认；剪贴板＋粘贴用于 Unicode 文本。先验证"写剪贴板→正确焦点→组合键粘贴→内容确认"。失败需明确报告，不静默降级。
- **Q5／协议与结果语义门禁** | 归属层：传输 | 根因：未明（Python barrier 超时） | 外层 RemoteXPC flags、message ID、请求关联及 barrier 语义尚未完整掌握。统一区分"未发送／已发送但结果未知／协议确认／观察到预期状态"。
- **Q5／兼容性矩阵与冒烟质量** | 归属层：SDK | 根因：已明 | 矩阵需记录主机 OS/架构、后端版本、Apple 主机包版本、设备型号、iOS build、DDI build、USB/无线、配对状态。下一版冒烟加入受控前置状态和具体后置断言。
- **Q5–Q6／证据与安装文档修正** | 归属层：SDK | 根因：已明 | 更新 `protocol.md` 后半部分仍称 raw 字典不可行的旧结论；原生后端可提供安装辅助，不镜像或捆绑 Apple pkg/DDI/framework。

**已否决（不再提）**

- 引入 XCTest／第三方手机 server 作为交付前提（来源：用户）。
- 复制 DDI/framework 即完成独立部署；恢复旧 services-async ABI 实验。D1、D3 和视频流只是后置，不是已否决项。

**验证资源**

- 跨平台与旧系统实机矩阵（Linux/Windows 主机、iOS 26 设备）。
- 语义验收与性能基线（可复位的测试页面/文本字段）。
- 发行条款核对（锁定版本许可证清单、Apple beta/pkg 条款）。

**前四周里程碑**

| 周 | 里程碑与退出条件 |
|---|---|
| 第 1 周 | 锁定 Python 依赖；复现发现、tap、swipe、Home、截图；调查 barrier 外层关联；原生/Python 同场景对照，输出延迟分解与成功/未知结果语义。 |
| 第 2 周 | 持久会话、描述符缓存、CLI/MCP 共用操作层；接入 launch、日志、Unicode 输入。内部 alpha 完成含中文输入的完整任务。UI 树调查到期给出结论。 |
| 第 3 周 | 帧与坐标契约、旋转和弹窗处理；按测量结果优化截图。至少一个非 Mac 主机从首次配对完成闭环；100 次受控交互及拔线/重连/取消验证。 |
| 第 4 周 | 干净环境安装复验；10 个代表任务各跑 5 次，目标至少 45/50；分别报告驱动失败与模型定位失败、延迟 p50/p95。发布带精确支持矩阵的试用版。 |

第四周只有在许可证目标、已测 Python 性能或安装成本构成明确障碍时启动 D3；若主要失败仍来自定位、旧帧、文本或协议完成语义，优先解决这些问题。
