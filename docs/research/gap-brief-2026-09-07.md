用户目标："先出一版只能在 macOS 27 + iOS 27（现在扩到 26）运行的简易验证版本"，最终像 adb 一样开箱即用、agent 时代可用。

## 今天一个新用户要用上它，需要做的事（现状）
1. 下载并安装 Xcode 27 beta（~10 GB xip；min macOS 26.4），首次启动装 XcodeSystemResources/MobileDevice 两个 pkg（这两步带来 CoreDevice 642.x、devicectl、DDI）。
2. 手机开开发者模式、USB 连接、解锁并点信任；iOS 27 手机自己拉 DDI，iOS 26 由主机挂载（需 USB，网络不行）。
3. clone 仓库，`make`（需要 Xcode 27 beta 的 SDK stubs，DEVELOPER_DIR 指向 beta）。
4. 运行 `bin/devicehubctl ...`（zsh wrapper），首次会自动预热 tunnel；用 `scripts/smoke_matrix.sh` 验收。
5. 没有安装器、没有签名分发的二进制、没有版本号、没有 MCP、没有 `doctor` 自检、协议漂移只在运行时以 CoreDevice 错误串形式暴露。

## 已知技术债/缺口（自查）
- helper 仍绑定 ~110 个私有 Swift 符号（seed 升级即可能断链）；raw-XPC 字典路径已抓包但未落地为实现。
- 每条命令新起进程、新 socket，tap ≈ 1.4 s（描述符发现 + 发送各 700 ms 尾等待）；无持久会话。
- 文本输入只有 HID 键位（ASCII），Unicode 需剪贴板路径（未验证）。
- UI 树无坐标（accessibility list-items 只有 caption）。
- 截图走 devicectl（1–2 s）；无画面流。
- barrier 在 pymobiledevice3 路径无回复（语义未明）。
- 冒烟门禁依赖真机随机状态（系统弹窗会遮挡），无可复位的测试 App。
- 错误分层已做（退出码 1/3/4/5），但没有面向用户的诊断命令（配对状态、开发者模式、DDI 状态、tunnel、服务集合一次性检查）。
- 许可证：pymobiledevice3 GPL-3；Apple pkg 不可再分发；仓库本身尚无 LICENSE 文件。
